    About Project

    Problem. Urban pipe networks lose water through leaks that can stay undetected for long periods; manual inspection is slow and reactive.

    Proposed solution. Compare flow, pressure and metered consumption with what is normal for each zone and hour, score the deviation, and raise alerts only when abnormal readings persist.

    Workflow

    1. Sensor data
    2. Validation
    3. Features
    4. Anomaly check
    5. Risk score
    6. Excess flow estimate
    7. Alert
    8. Incident
    9. Action

    Risk scoring (this demo). Score = flow excess not explained by consumption (35) + pressure drop (25) + flow-vs-consumption mismatch (25) + persistence (15). High demand raises flow and consumption together, so it is not scored as a leak. A pressure drop alone is not proof of leakage.

    Alerts. An alert needs a score of at least 50 for 3 consecutive readings; a single spike or sensor glitch does not create one. Each alert opens an incident (Open, Under investigation, Resolved).

    Estimated potential loss. Excess flow = observed flow - (expected flow + consumption increase). It is an estimate, not measured leakage or confirmed saved water.

    Future work. Flow/pressure sensors with an ESP32 gateway sending readings by MQTT/HTTP to a backend that runs the trained model. Not implemented in this website.
